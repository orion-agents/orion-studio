# Orion Studio 子计划包

## 目的

本目录把总计划
docs/plan/orion-studio-rebrand-migration-plan.md 拆成可交给 WorkBuddy
逐个执行的任务。每个子计划只覆盖一个边界，包含：

- 前置条件和禁止事项
- 精确的读写范围
- 按顺序执行的步骤
- 验收命令和预期证据
- 失败停止条件
- 回滚和交接格式

当前基线：

- 分支：init
- HEAD：d2779c3
- 当前仓库仍是 Zed 源码基线
- .workbuddy/、docs/research/ 和本目录都属于用户现有或本次计划内容，不能清理

## v2 续作入口

## 执行顺序

默认必须按以下顺序执行。不要让多个 WorkBuddy 进程同时修改同一个
worktree。

| 顺序 | 子计划 | 目标 | 是否允许改源码 |
| --- | --- | --- | --- |
| 00 | 执行手册 | 统一安全规则和交接格式 | 否 |
| 01 | 基线盘点 | 生成可重复的品牌/端点/发布清单 | 否，仅可写证据 |
| 02 | 身份契约 | 冻结命名、服务、许可证、兼容窗口 | 否，仅可写决策记录 |
| 03 | 运行时身份 | 迁移路径、环境变量、版本和运行时显示名 | 是 |
| 04 | 数据迁移 | 迁移旧配置、状态、远程目录和兼容读取 | 是 |
| 05 | 核心 package | 迁移主 package、binary 和默认构建入口 | 是 |
| 06 | CLI/API 协议 | 迁移 CLI、URL scheme、扩展 namespace | 是 |
| 07 | UI/资源/文档 | 迁移用户可见品牌、资源和说明 | 是 |
| 08 | 客户端服务 | 迁移 URL、登录、更新、遥测和 RPC 配置 | 是 |
| 09 | collab/远程 | 迁移服务端配置、部署和健康检查 | 是 |
| 10 | 打包/CI | 迁移平台安装包、artifact、workflow 和更新 | 是 |
| 11 | 回归/发布门禁 | 扫描、测试、安装、回滚和最终 Go/No-Go | 是，优先测试和证据 |

依赖关系：

~~~text
01 -> 02 -> 03 -> 04 -> 05 -> 06 -> 07 -> 08 -> 09 -> 10 -> 11
              |                                       |
              +----------- 每阶段都要保留 checkpoint --+
~~~

如果 Phase 2 之后发现 package/API 依赖无法按计划拆分，先暂停当前子计划，
新增一个更小的子计划，不得把多个阶段合并成一次全仓替换。

## 给 WorkBuddy 的调用方式

如果要让 HY3/WorkBuddy 从零开始，直接复制
[START-HY3-WORKBUDDY.md](./START-HY3-WORKBUDDY.md) 的全文作为首条任务。

每次只发送一个子计划，例如：

~~~text
请执行 docs/plan/subplans/03-runtime-identity-and-paths.md。
只执行这个子计划，不要提前执行后续子计划。
先完成 preflight；如果前置条件、命名契约或工作树边界不满足，立即停止并报告。
禁止全局搜索替换、git reset、git clean、删除用户数据、提交或推送。
完成后严格按子计划中的交接模板返回。
~~~

## 全局成功标准

单个子计划只有同时满足以下条件才算完成：

1. 只修改允许的文件范围。
2. 没有覆盖用户已有的 tracked、staged 或 untracked 内容。
3. 子计划中的测试实际运行过，并记录真实结果。
4. 结果可以由另一个 WorkBuddy 在干净上下文中复核。
5. 失败、跳过、环境限制和未决问题都明确写出。

“代码看起来改完了”不算证据。没有运行结果、diff 或日志的验收项必须标记
为未完成。

## 不可违反的停止条件

WorkBuddy 必须停止，不得自行做决定：

- 当前分支不是 init。
- 发现不在本次任务范围内的 tracked 或 staged 修改。
- 身份契约没有明确最终值，尤其是域名、App ID、URL scheme、许可证和兼容期。
- 需要删除、覆盖、移动用户数据，但没有迁移测试和回滚方案。
- 需要访问生产服务、真实凭据、签名证书或外部 secret。
- 修改范围会扩展到未列出的 crate、服务或平台。
- 测试失败原因不清楚，或依赖网络/服务但当前环境不可用。
- 需要修改另一个正在执行的子计划的文件。

## 交接结果模板

~~~text
子计划：Sxx <名称>
状态：DONE | BLOCKED | PARTIAL
执行分支：
基线 HEAD：
修改文件：
未修改但检查过的关键文件：
执行命令与结果：
验收项：
- Axx：PASS/FAIL/SKIP，证据：
失败或未决问题：
回滚方式：
建议下一步：
~~~

状态规则：

- DONE：所有验收项通过，没有未决阻塞。
- PARTIAL：有明确通过项，但仍有验收项未完成；不得进入依赖子计划。
- BLOCKED：遇到停止条件或外部依赖；不得修改范围外文件。
