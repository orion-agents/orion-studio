# S04：配置、状态、密钥和远程目录迁移

## 任务目标

在不丢失用户数据的前提下，把旧 Zed 数据迁移到 Orion 目录，并验证重复执行、
中断恢复、权限错误和回滚。此子计划不改主 package、CLI UI 或服务端数据库。

## 前置条件

- S03 DONE。
- S02 已批准旧目录、目标目录、兼容窗口和失败处理。
- S01 已列出配置、状态、密钥、扩展、缓存、日志和远程目录的分类。
- 已确认哪些内容可以复制，哪些内容必须重新生成，哪些内容禁止迁移。

如果没有明确的密钥迁移政策，状态必须为 BLOCKED；不要自行复制 token、
cookie、OAuth 文件或 SSH 私钥。

## 允许修改

- crates/paths/**
- crates/zed_env_vars/**
- 这些 crate 中与迁移直接相关的测试和 fixture。
- 如项目已有专用 migration 模块，只在该模块内实现，不新建平行存储体系。

禁止修改：

- crates/cli/**
- crates/client/**
- crates/collab/**
- 数据库生产迁移、Docker、安装器、UI 文案和服务 endpoint。

## 迁移分类

在代码和测试中明确区分：

| 数据 | 默认处理 | 失败时 |
| --- | --- | --- |
| 用户配置 | 迁移并保留备份 | 保留旧配置，报告错误 |
| workspace/session 状态 | 迁移或降级为空，按契约 | 不阻塞启动，保留诊断 |
| 扩展目录 | 按契约迁移 | 不删除旧目录 |
| 密钥/凭据 | 只有批准后迁移 | 失败则要求重新认证 |
| cache/temp | 不作为必须迁移数据 | 允许重新生成 |
| 日志 | 可选保留 | 不影响启动 |
| remote server 数据 | 只按远程契约迁移 | 不自动覆盖远端 |

## 执行步骤

### 1. 先写迁移状态模型

沿用现有项目的错误类型和持久化方式，定义可观察状态：

- 未发现旧目录。
- 新目录已存在。
- 发现旧目录，等待迁移。
- 迁移中。
- 迁移成功。
- 迁移失败但旧数据仍可读。
- 迁移已跳过或兼容窗口已结束。

状态必须支持重复启动时判断，不能用“目录存在”作为唯一成功标记。

### 2. 实现安全迁移算法

目标算法：

1. 计算旧根目录和新根目录，禁止路径穿越和模糊 glob。
2. 如果新目录已经有成功 marker，直接使用新目录，不重复复制。
3. 如果旧目录不存在，初始化新目录并结束。
4. 如果旧目录存在且新目录不存在，在同一父目录创建临时迁移目录。
5. 按分类复制或转换，保留允许的权限和文件类型。
6. 写入版本、源路径、目标路径、时间和迁移结果 marker。
7. 对允许原子操作的平台使用临时目录完成后 rename；不支持时使用现有安全
   文件工具，并在失败时保留旧目录。
8. 成功后保留可配置的旧目录备份或只读兼容入口，不自动永久删除。
9. 任一步失败都返回有上下文的错误，清理临时目录但保留旧数据和诊断。

不得把失败写成“忽略后继续”，不得使用危险的递归删除。

### 3. 增加测试矩阵

必须有临时目录测试，至少包含：

- 新装：没有旧目录。
- 升级：只有旧目录。
- 部分新目录：新旧目录同时存在。
- 已完成 marker：重复执行是幂等的。
- 迁移中断后重试。
- 文件权限不足。
- 磁盘写入失败或目标目录不可写。
- 大文件/符号链接/不支持的文件类型按契约处理。
- 迁移失败后旧目录内容和权限不变。
- 不迁移未批准的 secret。
- 迁移版本不兼容时安全停止。

### 4. 兼容读取测试

验证：

- 在兼容窗口内旧路径仍能被读取或提示迁移。
- 规范路径优先于旧路径。
- 旧 ZED_* 环境变量不会覆盖显式 Orion 配置。
- 迁移成功后不会反复提示。
- 兼容窗口结束后的行为是契约规定的错误或只读提示，而不是静默删除。

## 验收命令

~~~text
git diff --check
cargo +stable fmt --all -- --check
cargo +stable metadata --no-deps --format-version 1
cargo +stable test -p paths
cargo +stable test -p zed_env_vars
~~~

如果存在项目专用 migration test target，必须额外运行；如果没有，报告中写出
“当前仓库没有专用 target”，不能虚报。

## 验收标准

- 迁移是幂等的，失败不破坏旧数据。
- 任何删除动作都有明确批准和独立测试；首轮默认不删除旧目录。
- 配置、状态、扩展、密钥、cache、日志的策略不同且可审查。
- 迁移错误能到达调用层，不被静默丢弃。
- 测试覆盖新装、升级、中断、权限和回滚。
- 没有访问生产数据或真实凭据。

## BLOCKED 条件

- 目标目录、备份策略或兼容期限没有批准。
- 发现现有代码会递归删除旧目录但无法证明安全。
- 迁移需要修改 UI、CLI、远程 server 或数据库而这些不在范围。
- 测试必须使用真实用户目录、真实 cloud 或真实 secret。
- 迁移方案会改变协议或数据库 wire format。

## 回滚

测试失败时只清理测试临时目录。开发工作树回滚时只回滚本子计划 diff，
不要删除用户目录。线上回滚策略必须是“恢复上一版客户端/保留旧目录/读取备份”，
禁止直接把新 schema 降级覆盖旧数据。
