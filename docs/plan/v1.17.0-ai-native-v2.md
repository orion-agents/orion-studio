# v1.17.0 AI Native v2：Codex 式对话工作台改造计划

> 状态：**IN PROGRESS — prototype-to-implementation gap audit updated 2026-09-14**
>
> 分支核对：`release/orion-studio-v1.17.0`，HEAD `09d54f9f`
>
> 计划日期：2026-09-13
>
> 目标：AI Native 是以任务对话为唯一主舞台的工作台。它参考 Codex 的信息层级、操作节奏和控件语义，但不复制 Codex 商标、品牌文案、专有图标资产或字体；实现使用 Orion Studio 自己的主题 token、图标和无障碍文本。

## 1. 结论与决策

v1.17.0 当前已经完成了“让 AI 对话进入中心区域”的第一阶段，但**不满足本次 AI 原生目标**。问题不是配色、圆角或图标细节，而是它仍以传统 IDE 的 Pane / Tab 心智模型组织内容：

- 右侧 `TaskInspectorPanel` 明确定义并渲染了 `Changes / Files / Review` 三个固定 Tab；这正是截图中不希望继续存在的高频切换入口。
- 中央 `AiNativeConversationItem` 仍是通用 `Pane` 内的 `Item`。现有逻辑只在该 item 处于活动状态时隐藏 pane tab bar；打开普通 code item 后又回到 IDE tab 行为。
- 右侧文件和 Review 的原实现会把用户带回中心 code item / `AgentDiffPane`，使“中央永远是当前任务对话”不能成立。
- 现有 AgentPanel 已经能在新建线程菜单中列出 Native Agent、Terminal 和已注册的外部 ACP Agent；但 AI Native 左侧的“新对话”还没有将“先选择本次会话使用的 Agent”做成明确、可见且线程级的首步。

因此本计划的决定是：**保留 v1 已验证的单一会话数据源和中心 ConversationSurface，替换 Tab Inspector 与“打开文件即占用中央”的导航模型。** v2 不修改 ACP wire protocol、Orion Code sidecar 或 agent runtime；只在 Workspace 的 AI Native 呈现层、线程启动入口和任务证据呈现层改造交互。

## 2. 当前开发状态审计

| 能力 | 现状 | v2 处理 |

| 中央视觉契约 | `ConversationSurface::Center` 已有任务头和约 780px 居中阅读列 | 保留；按 v2 视觉规范精修，不改状态机 |

### 2.2 必须替换或收口的部分

| 当前实现 | 为什么不符合 | v2 目标 |
| --- | --- | --- |
| `TaskInspectorPanel` 的 `Changes / Files / Review` toggle strip | 用户必须记住内容在哪个 Tab；右侧成为一个小型 IDE | 替换为无 Tab 的 `TaskEnvironmentPanel`，采用单列、可展开的任务环境行 |
| `TaskFilesView` 作为独立 Files Tab | 完整文件树是仓库级工具，不是当前对话第一上下文 | 改为“任务涉及文件”及最近上下文摘要；完整浏览通过显式“在代码工作区打开”离开 AI Native |
| `TaskReviewView` 进入中心 `AgentDiffPane` | 取代对话主舞台并重新引入中心 Item / Tab 切换 | 在右侧显示变更摘要和局部预览；完整 diff 是明确的“在代码工作区审查”出口 |
| 按活动 Item 隐藏 tab bar | 只要激活其他 item，传统 tab row 即可重新出现 | AI Native 生效期间整个中心 Pane 不展示 tab bar；只有离开该布局后恢复 |
| AI Native 空状态的直接 `NewThread` | 未先说明本次会话的 Agent 型态 | 点击“新对话”统一先打开 Agent Chooser；选定后创建该草稿线程 |

## 3. v2 产品契约

### 3.1 一句话体验

打开 AI Native 后，用户始终看到：**左侧任务列表 → 中央完整 AI 对话记录与 Composer → 右侧当前任务环境**。没有内容 Tab；查看环境是展开一行，查看代码是明确离开此模式的动作，不会悄悄把对话替换掉。

### 3.2 不可妥协的界面规则

1. 中央区域的默认且持续主内容只能是当前任务的对话时间线、请求审批、提问、工具过程与 Composer；不得显示 editor tab row、文件 tab、行号或普通 code item。
2. 右侧不得有 `Changes / Files / Review`、二级页签或水平 Tab strip。所有环境信息以一个纵向可滚动面板中的 disclosure rows 呈现。
3. 左侧“新对话”一定先允许选择本次线程的 Agent 型态；选择只作用于该草稿线程，不偷偷改变其他已有线程。
4. 只有真实可用的 Agent、mode、模型、权限、worktree、plan、subagent 或 source 才可显示；ACP 未声明的能力不可用“空壳按钮”伪造。
5. 完整文件编辑、仓库树、Git 历史和复杂 diff 是显式的 **Open in Code Workspace** 出口。执行该动作后才进入现有 Agentic / Classic 代码工作区，保留该工作区已有 tab 语义。
6. AI Native ⇄ 代码工作区切换不得丢失当前 thread、草稿、消息队列、滚动位置、tool permission、未保存编辑或用户已有的 code tabs。

### 3.3 与参考界面的映射

附图所表达的目标是“一个任务工作台”，而不是把 IDE 的三个 dock 换成深色皮肤。v2 按下表实现等价交互语义。

| 参考语义 | Orion Studio v2 表现 | 交互规则 |
| --- | --- | --- |
| 顶部项目 / 任务身份 | 项目名、当前 thread 标题、更多菜单 | 单行；没有文件 tab strip。标题可按既有权限编辑。 |
| 左上新会话 | `New conversation` 主按钮 + 旁边 Agent chooser | 主按钮和快捷键都走同一个 chooser，而非一个直接创建、一个选择 Agent。 |
| 左侧任务轨道 | 搜索、Pinned、Recent tasks、当前 task 状态点 | 无多层导航 Tab；点击任务只切换中心对话和右侧环境。 |
| 中央时间线 | 复用 ConversationView / ThreadView 的消息、工具、审批、提问和 Composer | 维持一条真实 ACP timeline；卡片和间距仅是 Center surface 的表现差异。 |
| 右侧环境卡 | 无 Tab 的 `TaskEnvironmentPanel` | 每个条目可展开；展开不抢走中央输入焦点。 |
| 变更计数 | `+N −N` 与文件摘要 | 点击显示右侧局部 diff；不打开中央 editor。 |
| 工作区 / 分支 | Local worktree 与 branch disclosure | 只显示当前 thread / project 的真实路径与 Git 状态。 |
| Plan、Subagents、Sources | 有真实数据时才出现的环境条目 | 无数据时隐藏或显示说明态；不伪造数量。 |
| 全量代码审查 | `Open in Code Workspace` | 显式切换到既有代码 / AgentDiff 工作流，并提供 Return to task。 |

### 4.1 可交互验收稿（开发基线）

[打开 v2 AI Native 交互稿](evidence/v1.17.0-ai-native-v2.html)

`docs/plan/evidence/v1.17.0-ai-native-v2.html` 是本计划的**交互行为规格与视觉验收基线**，可直接在浏览器打开，不依赖网络、构建产物或产品运行时。它不是要打包进 Orion Studio 的 Web 资产，也不替代 GPUI 实现。

开发者必须按交互稿还原以下可验证流程，而不是只参考静态布局：

1. 点击左侧「新对话」或按 `⌘N`，弹出 Agent Chooser；选择 Orion Code、Native、外部 ACP Agent 或 Terminal 后，才创建对应的空草稿。
2. 点击左侧任务，中央只切换当前任务的真实对话记录，右侧无 Tab 地同步更新任务环境；Back / Forward 仅在任务历史存在时可用。
3. 点击右侧任意环境行，内容在原位置展开；Changes 中点击文件只显示右侧局部 diff，不能激活中央 editor 或让 pane tab bar 出现。
4. 点击「在代码工作区审查完整 diff」会先出现明确说明，再进入独立的代码工作区示意；`Return to task` 返回同一个 AI Native 任务，保留 thread 和 Composer 状态。
5. Composer 支持添加来源、Agent 标识、`⌘Enter` 发送；交互稿的模拟回复只用于说明时序，产品实现必须继续走真实 ACP / AgentPanel 状态。
6. 窄窗口先收起右侧环境、再折叠任务轨道；任何宽度下中央不会出现传统 editor tab row。

该稿有一个顶部「AI Native v2 交互规格」条，仅供设计 / 开发验收，不属于产品 UI。所有图标均为本地原创语义线框，生产实现必须映射为已有 GPUI theme token、`IconName` 和无障碍语义。交互稿的视觉 v2.1 已对齐 Orion Studio 现有 `editor_background`、`panel_background`、`elevated_surface_background`、`element_hover` 和 `border_variant` 五层语义：使用扁平 dock、紧凑列表、1px 分隔线、低圆角按钮和受限阴影；禁止把网页式渐变、悬浮大卡片或固定色值直接搬进产品。交互稿与本计划文字冲突时，以本计划的会话状态、ACP 能力边界和“中央对话持续可见”的约束为准。

### 4.2 尺寸与响应式边界

| 区域 | 宽度策略 | 最小状态 |
| --- | --- | --- |
| 左侧任务轨道 | 默认 264px；可收窄 / 折叠，延续现有 sidebar 持久化 | `< 1040px` 可折叠为图标 rail；任务列表通过快捷键 / 浮层可达 |
| 中央对话 | 弹性填充，正文阅读列最大 780px，Composer 与正文对齐 | 先收起右侧环境；绝不把正文挤成窄 dock |
| 右侧环境 | 默认 320px、最小 260px、最大随窗口而定 | `< 1180px` 默认收起为单个 Environment 按钮 / sheet |
| 顶部栏 | 固定单行，所有图标有 tooltip 与可访问名称 | 低优先级文字折叠为 icon / overflow，不产生第二行 tab |

所有颜色、间距、圆角、阴影、字体大小和 focus ring 必须调用现有 `crates/ui` token。深色截图是层级参考，不是硬编码调色板；浅色、高对比度与 reduced motion 同样属于验收范围。

### 4.3 顶部与图标规则

使用 Orion Studio 的 `IconName` / 外部已安装 Agent 的自有 SVG，不下载、不描摹、不打包 Codex 图标。下列控件只复用**语义与位置**：

| 控件 | 建议图标语义 | 行为 |
| --- | --- | --- |
| Sidebar | Panel left | 折叠 / 展开任务轨道，状态由 `aria-pressed` 表达 |
| Back / Forward | Arrow left / right | 只导航 thread / task 历史；无历史时禁用 |
| New conversation | Compose / Plus | 打开 Agent Chooser，不直接创建默认线程 |
| Add context | Plus | 打开现有上下文添加能力；失败向 Composer / toast 传达 |
| Agent selector | Agent 自有图标 + Chevron | 在空草稿发送前可更换该草稿 Agent |
| Send / Stop | Arrow up / Stop | 绑定现有发送、排队、取消语义，不能改变队列状态机 |
| Environment row | File diff / Folder / Branch / Plan / Link 等语义图标 | 可展开，有文本标签和键盘可达性 |
| More | Ellipsis | 放置低频 task / layout 操作，不能藏起必经的 Agent 选择 |

### 4.4 左侧任务轨道

- 第一屏只有 `New conversation`、Agent chooser、搜索、Pinned、Recent 和账户入口；不新增工作区级 project / git / outline 入口。
- `New conversation` 的整行可点击，旁边小 chevron 与整行进入同一个 chooser，避免“点击面积不同导致行为不同”。
- 每条任务只显示 title、Agent 小图标、状态（Running / Needs approval / Needs answer / Idle）和必要的未读 / 待办点；状态不能只以颜色表达。
- 选中已有 task 仅调用既有 AgentPanel 的活动线程切换，再驱动中央 ConversationSurface 与右侧 TaskEnvironmentPanel 订阅刷新。
- 任务搜索继续复用 thread metadata store；搜索结果不需要单独页面或 Tab。

### 4.5 中央对话区

- 保留 `ConversationSurface::Center`，其 header 是 task title、真实 agent 名称、真实运行状态和 overflow；不渲染 Pane tab bar。
- 保留现有消息虚拟化、markdown、tool calls、subagent cards、permission、elicitation、queue、compaction 与 Composer。只允许为 Center 表现添加卡片容器、阅读列和间距，不能复制状态或另起事件流。
- Composer 始终贴合中央底部阅读列；左侧 context 按钮、agent / model / mode 选择和发送 / 停止按钮只在后端能力真实声明时出现。
- 在空草稿中，header 与 Composer 显示已选择的 Agent；点击 Agent badge 可在第一次发送前重新打开 chooser。已有消息后不可无声变更线程 Agent，需新建线程。
- 从 message、环境条目或 `FocusAiNativeConversation` 返回任务时只恢复焦点与滚动，不新建线程、不清空草稿。

### 4.6 右侧 TaskEnvironmentPanel：无 Tab 的任务环境

`TaskInspectorPanel` 的产品角色被 `TaskEnvironmentPanel` 替代。它是右 dock 的单一面板，不含 horizontal tab strip、`TaskInspectorTab`、`ShowTaskChanges`、`ShowTaskFiles` 或 `ShowTaskReview` action。

| 环境行 | 默认状态 | 展开内容 | 数据和边界 |
| --- | --- | --- | --- |
| Changes | 有变更时默认展开 | 当前 task 影响文件、A/M/D、`+N −N`、单选局部 diff | 使用 Git / thread 已有事实源；文件局部预览留在右侧，绝不激活中央 editor |
| Local worktree | 折叠 | 项目根路径、工作树、远程 / 本地状态 | 路径可复制；没有 project 时明确显示 unavailable |
| Branch | 折叠 | 当前 branch、ahead / behind、dirty 摘要 | 使用真实 Git repository；无 Git 时隐藏，而不是显示空 branch |
| Commit or push | 折叠 | 变更概览与“在代码工作区打开 Git”动作 | 不在 AI Native 内复制完整 GitPanel 表单或历史 |
| Plan | 有真实 plan 才出现 | plan 摘要 / 当前步 / 进入线程内对应条目 | 仅使用 agent 已提供的计划数据；不构造假进度 |
| Subagents | 有真实子 agent 才出现 | 名称、状态、最新活动 | 只渲染已有 session / event 可证明的数据 |
| Sources | 有附加上下文时出现 | 文件、URL、图片等来源与移除操作 | 沿用现有 context ownership、权限和错误处理 |

局部 diff 的规则：一次最多展开一个文件，展开另一个时收起前一个；Accept / Reject 等改变代码的完整 review 操作不可在右侧复制第二套逻辑。右侧提供 `Open review in Code Workspace`，该显式动作再使用既有 `AgentDiffPane` / editor 流程。

## 5. Agent Chooser 与新会话模型

### 5.1 目标流程

```text
New conversation
      ↓
Agent Chooser popover / compact sheet
      ↓
select one available agent type
      ↓
create or focus one empty draft bound to that agent
      ↓
show it in central ConversationSurface; first send starts the session
```

### 5.2 可显示的选项

选项从 `AgentPanel`、Agent server store 和 ACP registry 的真实运行时状态派生，不在 UI 中写死一个“万能 Agent”：

| 类别 | 显示条件 | 创建行为 |
| --- | --- | --- |
| Orion Code | 受管 Orion Code / 默认 Native agent 已注册、可用 | 创建该 Agent 的新草稿；它是推荐默认项，不自动安装或自动认证 |
| Orion Agent | Native Agent 可用且其显示名与 Orion Code 不同 | 创建 Native Agent 草稿 |
| External ACP Agents | Agent server store 有已配置且可选择的 external agent | 每个外部 Agent 一行，沿用其名称和允许的自有图标 |
| Terminal | 当前 workspace 支持 terminal | 创建现有 Terminal thread；不会伪装成 AI chat |
| Add more agents | Registry 可用 | 跳转既有 ACP registry；返回后重新读取可用项 |

不可用、认证失败或协作会话禁止的 Agent 必须说明原因并禁用，不允许点击后静默回退为其他 Agent。选择结果属于**新草稿**；可将“最近使用”作为预选值，但 v2 的 AI Native chooser 不得把一次临时选择意外写成全局默认。是否保留原 AgentPanel 非 AI Native 的持久选择，须通过一个显式参数区分，防止回归既有用户偏好。

### 5.3 实现复用

目前 `AgentPanel::render_toolbar` 内部已有 `new_thread_menu_builder`，但数据枚举、菜单渲染和线程创建被闭包耦合。v2 先抽出无 UI 副作用的 `NewThreadChoice` / `available_new_thread_choices()` 与一个带 `persist_selection` 参数的创建入口：

- 现有 AgentPanel toolbar 继续用该模型渲染自己的菜单，保留 Classic / Agentic 行为。
- AI Native 左侧与空会话 header 用同一模型渲染 chooser，选择后通过同一 AgentPanel 线程创建路径执行。
- 这不是新的 Agent 注册表，也不改 ACP 协议；它仅消除两份菜单和两套选择状态。

## 6. 技术设计与迁移

### 6.1 保持核心边界

```text
ACP / Orion Code sidecar / external Agent
                 │
                 ▼
      AgentPanel (唯一 session、draft、queue、permission 宿主)
                 │ AgentPanelEvent + existing actions
                 ▼
 AI Native presentation adapters
 ┌───────────────┬────────────────────────────┬──────────────────────┐
 │ Threads rail  │ AiNativeConversationItem    │ TaskEnvironmentPanel │
 │ launcher      │ ConversationSurface::Center │ task-scoped evidence │
 └───────────────┴────────────────────────────┴──────────────────────┘
```

不新增 session store、thread metadata schema、ACP message、sidecar RPC 或 agent capability。`Workspace` / `Pane` 的改动仅限于 AI Native 呈现规则：在该 layout 激活期间稳定托管中心会话、隐藏中心 tab bar、把显式的“去代码工作区”动作路由到已有 workspace 能力。

### 6.2 中心 Pane 规则

1. `AiNativeConversationItem` 仍是每个 Workspace 的唯一中心会话 item，并继续订阅 `AgentPanelEvent`。
2. `sync_center_tab_bar` 改为按 `WindowLayout::AiNative` 判断，而不是按当前 active item 判断；AI Native 内所有中心 Pane 都不显示 tab bar。
3. 进入 AI Native 时激活 / 创建中心会话 item；离开时恢复 Pane 原有 tab bar predicate 与用户既有 items，不关闭或删除 code tabs。
4. 右侧的文件、变更和 review 入口不得调用“在当前 active Pane 激活 editor item”。它们只能：在右侧显示预览，或执行明确命名的 `OpenInCodeWorkspace` 路由。
5. `OpenInCodeWorkspace` 保存当前 AI task focus，切换至既有 Agentic / Classic（产品最终确定一种默认回退），再打开目标 editor / AgentDiff。`FocusAiNativeConversation` 可无损回到原 task。

### 6.3 Task Inspector 的替换策略

- 以 `TaskEnvironmentPanel` 取代 `TaskInspectorPanel`。改名后保留右 dock 的唯一 panel key 迁移策略，避免旧布局状态导致启动崩溃或重复面板。
- 删除 `TaskInspectorTab`、toggle group、三个 `ShowTask*` action、其 command palette filter 和与 tab index 相关的测试。
- `changes.rs` 中真实可复用的变更收集、diff 统计、thread / project 过滤抽成只读 adapter；`files.rs` 与 `review.rs` 中符合“任务环境摘要”的逻辑同样抽取。不要把原三个 View 实体嵌在新的面板内。
- 新面板管理每个 disclosure 的局部 UI state（展开行、单个已预览文件），但它不能拥有 Git、thread 或 AgentDiff 状态，也不持久化为全局 layout 偏好。
- 任何没有数据的 row 按表格规则隐藏或显示明确 unavailable 文案；不得为“像 Codex”而虚构 Plan、Subagents 或变更计数。

## 8. 自动化与人工验收清单

### 8.1 必须新增或改写的自动化测试

- AI Native 进入、thread 切换、terminal 切换、关闭再进入后中心只渲染一个 ConversationSurface。
- AI Native 内无论中心 pane 的 item 集合如何变化，都不显示 pane tab bar；Classic / Agentic 保持原 tab 行为。
- `TaskEnvironmentPanel` 没有 `TaskInspectorTab` / `ToggleButtonGroup`；Changes、worktree、branch rows 的 data filtering 仅针对活动 thread。
- 变更文件局部预览不调用当前 pane 的 editor activation；`OpenInCodeWorkspace` 才会执行明确 layout / item 路由。
- New conversation chooser 对 Native、external ACP、Terminal、unavailable Agent、collaboration restriction 和 Add More Agents 的行为正确。
- 选择 Agent 创建的 thread / draft 与现有 AgentPanel 创建路径有相同的 agent key、workspace 和错误传播。
- 线程已有消息后，agent badge 不允许 silent switch；创建新线程后可切换。
- Center reading column、Composer 对齐、right panel 响应式收起使用 GPUI visual bounds / debug selectors 断言。
- Dock lifecycle、panel activation priority、settings restore 和 command palette 的 AI-disabled filter 无回归。

### 8.2 Dev App 手工验收

1. 新建一个 project，切换 AI Native：中央只有对话和 Composer，顶部及中心无 editor tab row。
2. 左侧依次选 Native / Orion Code、一个已配置 external ACP Agent、Terminal：创建的草稿与标题显示正确，首次发送才启动对应 session。
3. 有修改的任务中展开 Changes、Local、Branch、Sources；点击文件只打开右侧预览。点击完整审查才明确进入代码工作区，Return to task 可恢复原 conversation。
4. 让 agent 产生 permission、question、tool call、queue、plan 或 subagent：中央和右侧仅显示真实状态，焦点不被 panel 抢走。
5. 在窄窗口下验证先收起 environment，再折叠 task rail；中央阅读列与 Composer 仍可操作。
6. 离开 AI Native 到 Agentic / Classic，确认代码 tab、普通 Git、Project、Outline 和 AgentPanel 原行为完整；再回来确认 thread、草稿、滚动与未保存文件不丢失。
7. 用深色、浅色、键盘 Tab / Shift-Tab、VoiceOver / accessibility inspector 检查每个纯图标控件都有名称、tooltip、焦点与禁用解释。

### 8.3 发布阻断条件

以下任一项未满足，v1.17.0 AI Native v2 不能标记完成：中心出现 Tab row；右侧出现 Changes / Files / Review Tab；新会话不能显式选择 Agent；代码预览无提示地覆盖中央对话；多个位置同时渲染同一个 ConversationView；或只通过单元测试、没有真实 Dev App 验收。
