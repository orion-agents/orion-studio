## 1. 结论

**当前不符合用户预期，且不能宣称 v1.17.0 AI Native v2 已完成。**

原因不在于没有开始实现，而在于存在两个完全不同的事实层：

| 层级 | 本轮观察 | 结论 |
| --- | --- | --- |
| 当前 dirty 源码 | 已有中心 `ConversationSurface::Center`、AI Native 全局隐藏中心 Tab、共享 `NewThreadChoice`、无 Tab `TaskEnvironmentPanel`、七类环境行、局部 diff、离开/返回代码工作区 action 与相应测试 | 已接近 v2 的信息架构，仍有产品交互和验收缺口 |
| `/Applications/Orion Studio Dev.app` | 安装包版本 `1.17.0 (20260912.081405)`、修改时间为 2026-09-12；实际窗口仍显示 `Changes / Files / Review` Tab，中央是旧的空任务状态 | **不是当前源码的可交付呈现，直接不符合 v2/v3 目标** |
| 用户文档 | `docs/src/getting-started.md`、`docs/src/ai/parallel-agents.md` 和 `docs/src/ai/agent-panel.md` 仍描述旧 Task Inspector、点击文件直接打开 editor / 恢复 tab 的旧路径 | 文档与新交互互相矛盾，不能发布 |
| 自动化 | 工作区内已有 v2 针对性 GPUI 测试；本轮观察到同一 dirty worktree 的 `agent_ui` 全量库测试为 `441 passed; 0 failed`。但并行开发仍在运行，且本轮 `cargo fmt --all -- --check` 曾报告 `task_environment.rs` import 排序差异 | 正向信号，不是冻结后的最终 CI 证据；必须在工作树静止后重跑 |

因此 v3 的判断是：**源码级约 70% 达到方向，运行时/交付级为 0% 达标。** 这个比例只用于排优先级，不是发布质量评分；v3 完成必须满足本文 §9 的全部门槛。

## 2. 预期符合度审计

### 2.1 与 v2 原型的逐项对照

| 预期 | 当前源码事实 | 当前 Dev App 事实 | v3 决定 |
| --- | --- | --- | --- |
| 中央永远是连续任务对话，无 editor Tab row | `sync_center_tab_bar` 按 AI Native layout 隐藏中心 pane tab bar；中心复用同一 `ConversationView` | 旧 App 仍是旧布局，未证明中心无 Tab | P0：构建、安装并截图验证；不得用源码或单测代替 |
| 先选择 Agent 再建立新会话 | 空状态及草稿 header 已调用共享 `build_agent_choice_menu`；已发送 thread 的 Agent badge 禁用并说明原因 | 未在 App 中验证 | P0：验证 Native/Orion Code、external ACP、Terminal、无可用 agent 与协作限制；补充“管理/添加 Agent”出口 |
| 左侧是紧凑 task rail | 沿用现有 Threads Sidebar/metadata，但没有本轮任务轨视觉和窄窗口验收 | 旧 App 列表仍是旧线程列表，文案/分组与原型不一致 | P1：只重排现有线程数据，不建第二状态 store |
| 右侧是无 Tab 的任务环境 | `TaskEnvironmentPanel` 的 `EnvironmentRow` 已覆盖 Changes、Local worktree、Branch、Commit or push、Plan、Subagents、Sources；局部 diff 留在右侧 | 旧 App 仍是 `Changes / Files / Review` Tab | P0：安装后验证无 Tab；P1：改善低价值行的摘要和动作 |
| 完整审查显式离开、再可见地回到任务 | `OpenInCodeWorkspace` 先显示确认 modal，`ReturnToAiNativeTask` 切回同一 AI Native task；title bar 有菜单入口 | 未在 App 中验证 | P0：完成一次取消、确认、Return 的真实窗口证据；P1：提升 Return 的可发现性 |
| 不伪造 ACP / Git / subagent / sources 数据 | Branch、Plan、Subagents、Sources 均从已有事实源读取，部分为空时隐藏 | 未做真实 project/agent 场景验证 | P0：真实数据、无 Git、无 sources、无 subagent 四类样本 |
| 类 Codex 的专业、简洁、原生编辑器风格 | 源码使用 Orion token 与低层级 panel 组件，方向正确 | 旧 App 的右侧 Tab 与通知遮挡让体验仍是“IDE 拼接面板” | P1：通过真实截图做视觉收敛，禁止网页大卡片/固定色值 |

### 2.2 必须优化的真实问题

1. **交付断层是最高优先级。** 开发中的 dirty 源码从未被安装到当前 Dev App；任何视觉讨论在安装新构建前都不能被用户确认。
2. **用户文档仍在教用户旧行为。** 旧文档写着 `Task Inspector` 三 Tab 和“点击文件打开 editor”；这会直接破坏 AI Native 的会话优先心智模型。
3. **Agent Chooser 只覆盖已配置选择，未完成“发现与管理”的闭环。** `NewThreadChoice` 当前只有 Native、外部 ACP、Terminal；缺少一个可发现的 `Manage agents…` footer/入口，也没有面向“未安装/未认证”的可解释项。不能伪造云 Agent，但必须有真实的管理出口。
4. **`Commit or push` 目前信息价值过低。** 当前内容是“Not duplicated here”。这符合不复制 GitPanel 的边界，却不如原型中的“当前分支 / ahead-behind / 一键进入代码工作区”有用。v3 应显示真实摘要与明确出口，不在右侧复制提交表单或历史。
5. **`Return to task` 仍偏隐藏。** action 已存在，代码工作区状态下由 title bar 菜单提供；需要在代码工作区顶部/状态区增加一个可发现、可键盘访问的“Return to task”入口，且只在由 AI Native 发起的往返中出现。
6. **左轨、响应式、无障碍还没有真实证据。** 现有 Threads Sidebar 可以复用，但需补任务状态文本、搜索空态、Pinned/Recent 分组、窄窗口收起顺序、浅色/高对比主题和 VoiceOver。
7. **环境噪声破坏演示质量。** 当前 Dev App 出现 `Invalid global tasks file` / `Invalid global debug scenarios file` toast。它应作为独立配置恢复问题处理：先用隔离测试 profile 验收 UI；不得删除或覆盖用户现有配置来取得“干净截图”。

## 3. v3 产品边界

### 3.1 保留的架构契约

- `AgentPanel` 仍是 ACP thread、草稿、队列、权限、持久化的唯一宿主。
- `AiNativeConversationItem` 只作为中心呈现宿主；不能新建第二个 `ConversationView`、thread store、queue 或 permission state machine。
- `TaskEnvironmentPanel` 是单一右侧 dock，使用真实 task/project facts；不重新嵌入 ProjectPanel、GitPanel、Outline、完整 AgentDiffPane 或 editor。
- 完整代码编辑、Git 历史和 hunk accept/reject 继续在现有 Code Workspace/AgentDiffPane 中完成。
- v3 不修改 ACP wire protocol、Orion Code sidecar、Agent runtime、会话持久化格式或默认 Agent 的后端安装策略。

### 3.2 v3 的界面结果

```text
┌──────────────────────────── Orion Studio chrome ───────────────────────────────┐
│ sidebar · history · project / task context · layout · window actions            │
├───────────────┬───────────────────────────────────────────┬────────────────────┤
│ TASKS         │ Current task                               │ ENVIRONMENT        │
│ New conv. ▾   │ task title · agent · real run state · …    │ Changes  +N −N   ▾ │
│ Search        │─────────────────────────────────────────── │ Worktree         ▾ │
│ Pinned        │                                            │ Branch           ▾ │
│ Recent        │       one real ACP conversation timeline   │ Commit / push    ▾ │
│ status text   │       tools · permissions · questions      │ Plan             ▾ │
```

视觉采用现有 Orion Studio token：editor/panel/elevated/hover/border 层、1px 分隔、低圆角、紧凑原生行高。参考 Codex 的是“会话主舞台 + 上下文随任务收敛”的结构，不复制其资产、色值、字体或品牌。

## 4. 实施计划

### Phase 0 — 冻结工作树并建立可运行基线（P0）

1. 记录当前 branch、HEAD、所有 dirty/untracked 文件及每一项归属；当前有并行开发/构建时，只指定一个 build owner，其他人不得同时运行全量 Cargo 命令。
2. 让负责 v2 源码的开发者先完成已有改动并恢复 `cargo fmt --all -- --check` 为通过状态；不以本计划修改源文件。
3. 执行冻结后的 `git diff --check`、`cargo fmt --all -- --check`、`./script/clippy` 和受影响 `agent_ui` 测试。
4. 使用项目既有开发构建/安装流程覆盖安装 **Dev App**，记录新 `CFBundleShortVersionString`、`CFBundleVersion`、构建 commit 和安装时间。不得把旧 `/Applications/Orion Studio Dev.app` 当作验收对象。
5. 使用隔离的开发 profile 或项目支持的测试配置入口启动；若全局 task/debug JSON 损坏，只记录精确文件和解析错误，先走备份/恢复流程，绝不删除用户生产配置。

完成条件：启动的 Dev App 能显示此次 commit 的诊断版本信息，且不再出现旧 `Changes / Files / Review` 实现。

### Phase 1 — 功能缺口收口（P0）

#### 1. Agent Chooser 完整闭环

1. 保持 `available_new_thread_choices()` 为唯一可选 Agent 数据模型；toolbar、左侧 New conversation、空草稿 header 与 Composer Agent chip 共用它。
2. 在选择器底部加入已有 Agent/ACP 配置页的真实 `Manage agents…` action；只有现有 action 无法复用时才新增路由。它不是虚构的 Agent 条目，也不能自动下载、安装或认证。
3. 按真实连接状态显示：可用、协作 workspace 禁用、认证/启动失败。失败消息从既有 connection/action 错误传递，不用静态“Cloud”占位。
4. 测试 one-off chooser 选择不会写全局默认；toolbar 的原有持久选择保持不回归；已有消息 thread 不得改后端。

#### 2. 任务环境信息价值

1. 保留七行结构和“无真实数据则隐藏”的规则。
2. 将 `Commit or push` 改为真实、短摘要：branch/upstream、ahead/behind、是否有 task changes；提供 `Open Git in Code Workspace`。没有 remote 时说明 `No upstream configured`，不显示伪进度。
3. `Changes` 维持“一次一份局部预览”，增加 preview 加载失败/无 task-owned diff 的解释；禁止任何文件点击激活中心 editor。
4. `Sources` 只展示 Composer 实际 mention/context，操作仍通过 Composer 的既有 ownership 完成；v3 不在右 dock 发明独立附件状态。

#### 3. Code Workspace 往返的可发现性

1. 保留退出前的确认层：取消零副作用，确认明确进入 Agentic code workspace。
2. 仅当本次 code workspace 由 AI Native 启动时，在顶部/状态区呈现 `Return to task`；菜单与 command palette 同步保留此 action。
3. Return 必须恢复同一 task、草稿、排队消息、滚动和焦点，不能创建会话或覆盖用户已有 editor tabs。

完成条件：每项都有最小 GPUI 回归测试和真实窗口证据，且 P0 操作无静默 layout 切换。

### Phase 2 — 任务轨、中心会话与视觉密度（P1）

1. 将现有 Threads Sidebar 以 AI Native 专用 presentation 渲染为 `TASKS`：New conversation、搜索、Pinned、Recent、当前选中与状态文本。复用 thread metadata store，不建第二列表数据源。
2. 每项状态有文字/tooltip（Running、Needs approval、Needs answer、Idle），颜色仅作为辅助；终端 thread 必须继续以 terminal 身份显示。
3. 中央 header 只保留 title、Agent、真实运行状态、低频 overflow；Composer 与 780px 阅读列对齐，agent/mode/model 只在真实 capability 声明时显示。
4. 宽度策略：`<1180px` 先收起 Environment，`<1040px` 再折叠 task rail；中央从不回退为窄 dock 或出现 tab row。
5. 以 Orion token 收敛 hover、selected、focus、disabled、loading、permission、empty/error 状态；禁止网页化大卡片和硬编码深色。

完成条件：1440×900、1180×800、1100×760 三种窗口尺寸，以及深色/浅色/高对比模式截图均能清楚展示“左任务、中过程、右事实”。

### Phase 3 — 文档、真实验收与发布判断（P0）

1. 更新 `docs/src/getting-started.md`、`docs/src/ai/parallel-agents.md`、`docs/src/ai/agent-panel.md`：删除三 Tab、点击文件直接打开 editor、普通 tab 回归等旧描述；写明 Agent Chooser、局部 diff、Code Workspace 确认与 Return to task。
2. 新增可定位证据目录 `docs/plan/evidence/v1.17.0-ai-native-v3/`，存放无敏感数据的截图/录屏说明、窗口尺寸、theme、构建版本和场景说明。
3. 对 Native/Orion Code、external ACP、Terminal、无 Git、changes、plan、subagent、sources、permission/elicitation、Code Workspace 往返、AI disabled 各执行一次真实路径。没有可用 external ACP 时，明确记录为环境阻塞而非模拟完成。
4. 再次运行格式、clippy、相关测试和安装后启动检查；最后才进入签名、公证和 GitHub Release 流程。

## 6. 真实 Dev App 验收脚本

1. 启动带本轮构建版本的 Dev App，截图记录版本、项目和窗口尺寸。
2. 切换 AI Native：确认中央没有 editor tab row，右侧没有 `Changes / Files / Review`，左侧显示任务轨。
3. 从 New conversation 依次验证 Native/Orion Code、一个已配置 external ACP、Terminal；选择后只创建草稿，首次发送才启动 session。
4. 对已有消息 thread 点击 Agent：确认其不可切换且给出新建会话说明。
5. 让任务产生变更；展开 Changes、Branch、Plan、Subagents、Sources；点击文件只在右侧看局部 diff。
6. 点击 `Open review in Code Workspace`：确认取消无变化；确认后进入 code workspace；从可见 `Return to task` 返回并确认同一草稿/滚动/任务。
7. 在无 Git 项目、没有 sources、没有 subagent、ACP 权限问题与窄窗口下重复关键路径；确认无假数据、无越界状态、无传统 tab 复活。
8. 在浅色、深色、高对比及键盘/VoiceOver 下检查 pure-icon 控件。测试配置的错误 toast 必须另行记录，不能裁切或忽略。

## 7. 并行协作边界

| 工作流 | 可并行内容 | 不得同时触碰 |
| --- | --- | --- |
| A：核心交互 | `agent_panel.rs` 的 chooser、`task_environment.rs` 的 facts/row、相关测试 | B 的文档与证据目录；避免改同一 Rust 文件 |
| B：导航与视觉 | task rail presentation、Code Workspace Return 可见入口、响应式/无障碍 | A 的 Agent choice model 与 environment facts |
| C：文档与验收 | 三份用户文档、v3 evidence、Markdown checks、Dev App 手工记录 | 任何 source rewrite；只反馈缺口 |
| D：构建 owner | format/check/test/build/install 的串行执行 | 不进行产品逻辑开发，不与其他 Cargo 全量构建并发 |

每个工作流结束必须报告：修改文件、实际命令及退出码、截图绝对路径、已知未完成项、当前 `git status`。任何一个工作流都不得将未提交本地改动、旧 App、模拟 HTML 或单测单独描述成“发布完成”。

## 8. 风险与决策

| 风险 | 防护与决定 |
| --- | --- |
| 旧 Dev App 被误认为最新实现 | 将 CFBundleVersion/commit/安装时间写入每份视觉证据；不匹配即验收失败 |
| 多 agent 同时 Cargo 构建/format | Phase 0 指定 build owner；先 `--check`，后由文件 owner 格式化 |
| 为了符合原型而伪造 Agent/plan/subagent/source | 所有行只读真实事实；缺能力时提供管理入口或隐藏，并记录产品缺口 |
| 右侧重长成第二个 IDE | 仅摘要/局部 preview；完整 code/Git/review 必须走 Code Workspace |
| Return action 隐藏或丢状态 | 只对 AI Native 往返显示可见入口；为 task/draft/focus/scroll 建回归和手工证据 |
| 全局 JSON 解析 toast 污染体验 | 以隔离 profile 验收；单独修复/迁移配置，绝不删除用户数据作为 UI 修复 |
| 文档继续描述旧 Tab | 文档更新是 v3 P0，与源码/Dev App 同等的发布门槛 |

## 9. 完成定义

v3 仅在以下所有条件同时成立时可标记为 `DONE`：

- 安装运行的 Dev App 与当前冻结 commit 一致，且用户可见页面不含旧 `Changes / Files / Review` Tab；
- 中央连续对话、Agent-first 新会话、右侧真实无 Tab 环境、显式 Code Workspace 往返均在真实窗口中通过；
- 现有 ACP/AgentPanel 生命周期、Terminal、Classic/Agentic、权限、队列和已有 code tabs 无回归；
- Agent 管理入口、Commit/push 信息价值、Return 可发现性、任务轨/响应式/无障碍的 v3 改善均有落实或被明确降级并经产品决定；
- 用户文档、交互稿、自动化、Dev App 截图/录屏和构建版本彼此一致；
- 冻结后 format、clippy、相关测试、安装启动检查和 Markdown 检查都有本轮可复核输出；
- 任何签名、公证、GitHub Release 只在以上产品验收完成之后另行执行。
